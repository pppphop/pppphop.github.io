# P3上机-问题思路汇总

## 第一题

### 指令格式

`REVI`-`rs`-`rt`-`imm16`

I型计算类指令，机器码为`101101`

### 指令描述

将`rs`中数值高imm16位翻转置于低位，剩余位置不变置于高位，将结果存入`rt`中。（保证`imm16`严格小于32）

### RTL语言

```
temp <- GRR[rs]
result <- temp[31-imm16:0]||reverse(temp[31:32-imm16])
GPR[rt] <- result
```

## 第二题

### 指令格式

`BLZ`-`rs`-`rt`-`offset`

I型跳转类指令+I型计算类指令，机器码为`011000`

### 指令描述

比较`rs`、`rt`中数据先导零的个数，决定跳转方式与存储数据。

### RTL语言

```
temp1 <-count_leading_zeros(GPR[rs])
temp2 <-count_leading_zeros(GPR[rt])
if (temp1 == temp2) 
	PC <- PC + 4 + sign_ext(offset||00)
else if (temp1 > temp2)
	PC <- PC + 4
	rs <- temp1
else
	PC <- PC + 4
	rs <- temp2
```

## 第三题

### 指令格式

`LWF`-`base`-`rt`-`offset`

I型访存类指令。

### 指令描述

Load Word with Filter

根据`filter`1的个数决定访存所得数据存入`rt`还是`(rt+1)mod32`中。

### RTL语言

```
vaddr <- GPR[base] + sign(offset)
paddr <- vaddr[31:2]||00
memword <- memory[paddr]
filter <- memword And GPR[rt]
ones <- count_ones(filter)
if (ones mod 2 == 0)
	GPR[rt] <- memword
else
	GPR[(rt+1)mod32] <- memword
```

## 解题思路

T1难点在反转，用两个$splitter$序号相反即可，也得点蛮久。

T2坑点好像是在用$31$减还是$32$，特殊处理找不到$1$的情况。这题想做对有难度，记得当时我卡了很久。

T3我十分钟一遍过了，只记得过了两道头脑一下清醒了，思路清晰的拿下了这道题。解法好像是只改了顶层，在顶层加点东西就行。

## 笔者的话

如果发现我的解题思路越写越简略，这是正常的，因为实在不记得了555……

然后讲一讲上机的一些感受，毕竟P3是第一次进入闯关，很多人也会挂在这，我们这届通过率只有百分之三十几，并不高。首先是上机前你会很紧张，真的非常紧张，来回踱步，在机房里等待开始时更是如此，可以尝试深呼吸，想一想其他的事转移一下注意力。如果你在过两题之前发现卡住了，这时候心态包崩的。如果过了两题，那最后一题基本上你的心态会很好，从容优雅的解决最后一道题，因为你心里已经知道自己已经通过了。

然后是报错信息的问题。相信学长学姐也都教过大家裸交的方法，如果直接裸交自己课下的代码能过两三个点，那基本上就没什么问题，这个基本适用于P5和P7之外的每一关。比如P3，测试点是比较少的，裸交五个点都过了仨，那肯定课下是没问题了。但是你在做加指令题时发现错误信息是课下的指令，比如`lw`，`ori`出错，就会怀疑自己的课下。其实这是评测机机制导致的。他只会检测你有`GRFwe=1 || DMwe=1`的指令，即写寄存器或写内存，这在做P4的过程中就能理解了。可能是新加指令没有写寄存器、写内存，或者你的`GRFwe`错了、没接线等。

最后是闯关制的问题。P3-P7一共有三次容错，也就是你可以挂三次P仍然通关计组实验。不用太担心，虽然这个上机贯穿学期始终，花了大量的时间，但是大部分人是可以通关的，可能不是同一批，但几乎不影响分数。
