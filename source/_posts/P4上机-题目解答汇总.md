# P4上机-问题解答汇总

## 第一题

### 指令描述

`spe`-`rs`-`rt`-`rd`-`zero`-`brc`(brc = 101001)

`special` `$rs` `$rt` `$rd` 0 `funct`     000000 5位寄存器地址 5位寄存器地址 5位寄存器地址 00000 101001

R型指令

### RTL语言

```
temp <- GPR[rs][4:0]
if temp < 25 && count_ones(GPR[rt][temp+7:temp]) mod 2 == 0
	GPR[rd] <- reverse(GPR[rt])
else
	GPR[rd] <- GPR[rt]
```

没有什么难点和坑点，模拟着去做就行。设出一个`wire`/`reg`类型`temp`，一个计数器`reg cnt`，循环找出`GPR[rt]`从`temp`到`temp+7`位的1的个数。反转也可使用一个循环实现。

```
//ALU.v
reg [4:0] temp;
reg [31:0] cnt,ans;
integer i;
always @(*) begin
    temp = A[4:0];
    cnt=0;
    if(temp<25) begin
        for(i=temp;i<=temp+7;i=i+1) begin
            cnt=cnt+B[i];
        end
        if(cnt[0]==0) begin
            for(i=0;i<31;i=i+1) begin
                ans[i]=B[31-i];
            end
        end
        else ans=B;
    end
    else ans=B;
end
```

## 第二题

### 指令描述

`CABC`-`rs`-`rt`-`offset`（CABC = 111100）

`opcode` `$rs` `$rt` `offset`     111100 5位寄存器地址 5位寄存器地址 16位立即数

I型指令

### RTL语言

```
cross1 <- GPR[rs][23:16]||GPR[rt][7:0]||GPR[rs][31:24]||GPR[rt][15:8]
cross2 <- GPR[rt][7:0]||GPR[rs][23:16]||GPR[rt][31:24]||GPR[rs][15:8]
xor_result <- cross1 ^ cross2
cnt1 = count_zero(xor_result[31:16])
cnt2 = count_zero(xor_result[15:0])
if cnt1 == cnt2
	PC <- PC + 4 + sign_ext(offset)
else
	GRF[rt] <- xor_result
```

这题非常卡人！有很多地方容易出bug。本人在考场上被这题硬控一个小时后跳过，去把第三题做过以后，回来推倒重写了此题，结果一遍就过了。在这里不给出代码了，只讲解思路。

首先，在ALU里执行`cross1`，`cross2`，`xor_result`，`cnt1`，`cnt2`，并令一个输出端口`equal=(cnt1==cnt2)`。

然后将`equal`传入`ctrl`，用于对`NPCop`以及`GRFwe`进行选择。

至于跳转，建议单开一个通路，不要借用`beq`的通路，容易出bug。

## 第三题

### 指令描述

`LHBOC`-`rs(base)`-`rt`-`offset`（LHBOC=101101）

### RTL语言

```
vAddr <- GPR[rs] + sign_ext(offset)
pAddr <- vAddr[31:2]||00
memword <- Memory[pAddr]
temp1 <- count_ones(memword[15:0])
temp2 <- count_ones(memword[31:16])
if temp1 >= temp2
	GPR[rt] <- sign_ext(memword[15:0])
else
	GPR[rt] <- sign_ext(memword[31:16])
```

### P3思路及解答：

我们发现他的数据通路和`lw`是基本一致的，我们控制信号可以几乎完全照搬，只需要修改写入寄存器的值（`WD`）即可。ALU被我们用来计算地址了，那么最后的`WD`肯定不能从`ALUans`中得来，我们发现需要对`DMrd`做运算，这个时候我们不得不新增一个模块去运算或者直接加在DM里。在上机时为了稳妥，我直接在DM中增加了一个组合逻辑块来实现得到我们需要的结果`DMans`。

```
//dm.v:
module DM(
    input [31:0] DMaddr,
    input [31:0] DM_WD,
	input [31:0] PC,
    input DMWr,
    input clk,
    input reset,
	output reg [31:0] DMans,
    output [31:0] DMrd
    );
reg [31:0] cnt1,cnt2;
//...
    
    
always @(*) begin
	cnt1=0;
	cnt2=0;
	for(i=0;i<16;i=i+1) begin
		cnt1=cnt1+DMrd[i];
	end
	for(i=16;i<32;i=i+1) begin
		cnt2=cnt2+DMrd[i];
	end
	if(cnt1>=cnt2) begin
		DMans={{16{DMrd[15]}}, DMrd[15:0]};
	end
	else begin
		DMans={{16{DMrd[32]}}, DMrd[31:16]};
	end
end	
```

之后我们只需在将控制信号`WDslt`设为$3$，顶层加入这一根线即可。

```
//ctrl.v:
LHBOC: begin
//...
WDslt=3;	
//...
end
```

```
assign WD = (WDslt==2'b00) ? ALUans:
				(WDslt==2'b01) ? DMrd:
				(WDslt==2'b10) ? PC4 : 
				(WDslt==2'b11) ? DMans:
				0;
//...

DM _dm(
    	//...
		.DMans(DMans),
    	//...
		);
```

这样，我们仅通过<strong>“模块化的增添”</strong>便完成了指令的增加，没有影响到任何其他指令，并且比较清晰好检查，个人觉得算是课上的一种最优解。
